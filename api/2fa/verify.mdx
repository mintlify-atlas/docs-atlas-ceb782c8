Auth Backend's 2FA verification endpoint is the final step of a login flow where `twoFactorRequired: true` was returned. After a successful password check, the server issues a short-lived `pre_auth_token` cookie that holds the user's identity in Redis until this endpoint exchanges it for real session cookies (`access_token` and `refresh_token`). This page covers the request contract, cookie lifecycle, replay protection, and all error cases.

<Info>
  Tokens **never appear in the response body** — they travel exclusively as HttpOnly cookies. This prevents JavaScript running on the page from reading or leaking session credentials.
</Info>

---

## Endpoint

```
POST /api/v1/auth/2fa/verify
```

---

## Authentication

This endpoint does **not** require a Bearer token or `access_token` cookie. Instead, the browser must carry the `pre_auth_token` HttpOnly cookie that was set during the preceding `POST /api/v1/auth/login` call. The cookie is read automatically; you do not include it in the request body.

<Warning>
  If the `pre_auth_token` cookie is missing — for example because it expired or the request comes from a different browser session — the endpoint returns `400 Bad Request` immediately.
</Warning>

---

## Rate Limit

All `/api/v1/auth/2fa/**` endpoints share a single bucket: **5 requests per 15 minutes** per client IP (unauthenticated bucket, since no session exists yet). Exceeding the limit returns `429 Too Many Requests` with an `application/problem+json` body.

---

## Request

**Content-Type:** `application/json`

<ParamField body="code" type="string" required>
  A 6-digit TOTP code from your authenticator app **or** a single-use backup code issued during 2FA enrollment. Must match `^[a-zA-Z0-9]{6,10}$`.
</ParamField>

<Tabs>
  <Tab title="TOTP Code">
    ```json totp-request.json
    {
      "code": "837204"
    }
    ```
  </Tab>
  <Tab title="Backup Code">
    ```json backup-request.json
    {
      "code": "A1B2C3D4"
    }
    ```
  </Tab>
</Tabs>

---

## Response

### `200 OK`

2FA was verified successfully. The server:

1. Validates the code (TOTP first, then backup code fallback).
2. Marks the TOTP code as used in Redis to block replays (backup codes are consumed from the database directly, so they are inherently one-use).
3. Deletes the `pre_auth_token` from Redis and clears its cookie.
4. Creates a new `RefreshToken` record (the session) and issues a signed JWT.
5. Writes `access_token` and `refresh_token` as HttpOnly cookies.

<ResponseField name="message" type="string">
  Human-readable confirmation string, e.g. `"Login successfully completed"`.
</ResponseField>

```json 200 Response Body
{
  "message": "Login successfully completed"
}
```

**Cookies set on `200 OK`:**

| Cookie | Attributes |
|--------|-----------|
| `access_token` | HttpOnly, Secure, SameSite=Strict |
| `refresh_token` | HttpOnly, Secure, SameSite=Strict |
| `pre_auth_token` | Cleared (Max-Age=0) |

---

## curl Example

```bash verify-2fa.sh
curl -X POST https://api.example.com/api/v1/auth/2fa/verify \
  -H "Content-Type: application/json" \
  --cookie "pre_auth_token=<pre_auth_token>" \
  -c cookies.txt \
  -d '{"code": "837204"}'
```

<Tip>
  In a browser context the `pre_auth_token` cookie is sent automatically. In API clients or integration tests, pass it via `--cookie` as shown above.
</Tip>

## Replay Protection

TOTP codes are valid for a 30-second window but can be intercepted and resubmitted within that window. Auth Backend stores every consumed TOTP code in Redis for the duration of the TOTP period. A second request carrying the **same code** within that window is rejected even though it is mathematically valid.

Backup codes are consumed from the database on first use and are immediately invalidated — no Redis tracking is needed.

---

## Error Codes

| Status | `application/problem+json` detail | Cause |
|--------|----------------------------------|-------|
| `400 Bad Request` | `"Pre-auth token is missing. Please login first."` | The `pre_auth_token` cookie is absent or was already consumed. |
| `400 Bad Request` | `"Invalid or expired pre-auth token"` | The pre-auth token does not exist in Redis (expired or already used). |
| `400 Bad Request` | `"Invalid 2FA code"` | The TOTP code is wrong, or no backup code matched. |
| `400 Bad Request` | `"Code already used. Please wait for a new code from your authenticator app."` | TOTP replay detected within the same 30-second window. |
| `400 Bad Request` | `"code"` validation error | `code` is blank or does not match `^[a-zA-Z0-9]{6,10}$`. |
| `429 Too Many Requests` | `"Too many requests, please wait"` | Rate limit exceeded (5 req / 15 min). |
