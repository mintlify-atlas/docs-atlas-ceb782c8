The Auth Backend **password reset** flow lets users recover their account using a time-limited, one-time 6-digit OTP delivered by email. The flow spans three endpoints in sequence: `POST /api/v1/auth/forgot-password` dispatches the code, `POST /api/v1/auth/verify-otp` validates it without consuming it (allowing the frontend to confirm the code before revealing the new-password form), and `POST /api/v1/auth/reset-password` consumes the code, updates the password, and revokes all active sessions. All three endpoints share a single rate-limit bucket.

## Rate Limit

<Warning>
  `forgot-password`, `verify-otp`, and `reset-password` share the **`OTP`** rate limit bucket: **3 requests per hour** per IP address. This limit applies across all three endpoints combined. Exceeding it returns `429 Too Many Requests`.
</Warning>

## Step 1 — POST /api/v1/auth/forgot-password

**Request a password-reset OTP.**

### Authentication

No authentication is required. This endpoint is publicly accessible.

### Request Body

<ParamField body="email" type="string" required>
  The email address of the account to recover. Must be a valid email format.
</ParamField>

### Example Request Body

```json forgot-password-body.json
{
  "email": "jane@example.com"
}
```

### Response

**200 OK** — Always returned regardless of whether the email exists. This prevents user enumeration.

<ResponseField name="message" type="string">
  Always `"If the email is registered, you will receive a recovery code shortly."`.
</ResponseField>

```json 200-forgot-password.json
{
  "message": "If the email is registered, you will receive a recovery code shortly."
}
```

### cURL Example

```bash forgot-password.sh
curl -X POST https://api.example.com/api/v1/auth/forgot-password \
  -H "Content-Type: application/json" \
  -d '{"email": "jane@example.com"}'
```

## Step 2 — POST /api/v1/auth/verify-otp

**Validate the OTP without consuming it.**

This intermediate step lets the frontend confirm that the user's code is correct before displaying the new-password form. The OTP remains valid and usable for the `reset-password` step after this call.

### Authentication

No authentication is required. This endpoint is publicly accessible.

### Request Body

<ParamField body="email" type="string" required>
  The email address for which the OTP was requested. Must be a valid email format.
</ParamField>

<ParamField body="code" type="string" required>
  The 6-digit numeric OTP received by email. Must match the pattern `\d{6}`.
</ParamField>

### Example Request Body

```json verify-otp-body.json
{
  "email": "jane@example.com",
  "code": "839201"
}
```

### Response

**200 OK** — The OTP is correct and has not expired. It is **not** consumed.

<ResponseField name="message" type="string">
  Always `"Code is valid. You can now reset your password."`.
</ResponseField>

```json 200-verify-otp.json
{
  "message": "Code is valid. You can now reset your password."
}
```

### cURL Example

```bash verify-otp.sh
curl -X POST https://api.example.com/api/v1/auth/verify-otp \
  -H "Content-Type: application/json" \
  -d '{
    "email": "jane@example.com",
    "code": "839201"
  }'
```

## Step 3 — POST /api/v1/auth/reset-password

**Set a new password and revoke all active sessions.**

### Authentication

No authentication is required. This endpoint is publicly accessible.

### Request Body

<ParamField body="email" type="string" required>
  The email address of the account. Must be a valid email format.
</ParamField>

<ParamField body="code" type="string" required>
  The 6-digit OTP received by email. Must match `\d{6}`. This call **consumes** the code — it cannot be reused.
</ParamField>

<ParamField body="newPassword" type="string" required>
  The new password. Must be **at least 8 characters**, contain **at least one uppercase letter**, and contain **at least one digit**. Hashed with BCrypt (cost 12) before storage.
</ParamField>

### Example Request Body

```json reset-password-body.json
{
  "email": "jane@example.com",
  "code": "839201",
  "newPassword": "NewSecret9!"
}
```

### Response

**200 OK** — Password updated; all sessions revoked.

<ResponseField name="message" type="string">
  Always `"Password updated successfully. Please log in with your new password."`.
</ResponseField>

```json 200-reset-password.json
{
  "message": "Password updated successfully. Please log in with your new password."
}
```

### cURL Example

```bash reset-password.sh
curl -X POST https://api.example.com/api/v1/auth/reset-password \
  -H "Content-Type: application/json" \
  -d '{
    "email": "jane@example.com",
    "code": "839201",
    "newPassword": "NewSecret9!"
  }'
```

## Full Flow Overview

<Steps>
  <Step title="Request the OTP">
    POST to `forgot-password` with the user's email. If the account exists, a 6-digit code is stored in Redis with a TTL set by `app.otp.expiration-minutes` and emailed via Resend.
  </Step>
  <Step title="Check inbox and validate">
    The user reads the code from their email and optionally POSTs to `verify-otp` to confirm it is correct before proceeding.
  </Step>
  <Step title="Submit new password">
    POST to `reset-password` with the email, the OTP, and the desired new password. On success:
    - The new password is hashed and persisted.
    - The OTP is marked as used and cannot be replayed.
    - All active `RefreshToken` records for the user are revoked, signing out every device.
  </Step>
  <Step title="Log in again">
    The user logs in via `POST /api/v1/auth/login` with the new credentials.
  </Step>
</Steps>

<Info>
  The OTP expiry is controlled by the `app.otp.expiration-minutes` environment variable. After expiry, a new code must be requested via `forgot-password`.
</Info>

## Error Codes

<AccordionGroup>
  <Accordion title="400 Bad Request — Invalid or expired OTP">
    Returned by `verify-otp` and `reset-password` when the submitted code is incorrect, has already been used, or has expired.

    ```json 400-invalid-otp.json
    {
      "type": "about:blank",
      "title": "Bad Request",
      "status": 400,
      "detail": "Invalid or expired OTP code",
      "instance": "/api/v1/auth/reset-password"
    }
    ```
  </Accordion>

  <Accordion title="400 Bad Request — Validation failure">
    Returned when any field fails Bean Validation (e.g., `code` not 6 digits, `newPassword` too short or missing a digit/uppercase letter).

    ```json 400-reset-validation.json
    {
      "type": "about:blank",
      "title": "Bad Request",
      "status": 400,
      "detail": "Password must contain at least one uppercase letter and one number",
      "instance": "/api/v1/auth/reset-password"
    }
    ```
  </Accordion>

  <Accordion title="429 Too Many Requests — Rate limit exceeded">
    Returned when the shared `OTP` bucket is exhausted (3 combined requests/hour across all three endpoints per IP).

    ```json 429-otp.json
    {
      "type": "about:blank",
      "title": "Rate Limit Exceeded",
      "status": 429,
      "detail": "Too many requests, please wait",
      "instance": "/api/v1/auth/forgot-password"
    }
    ```
  </Accordion>
</AccordionGroup>

<Note>
  `forgot-password` always returns `200 OK` regardless of whether the email is registered. This is intentional to prevent user enumeration attacks.
</Note>
