Auth Backend is a production-ready authentication service built with Spring Boot 4 and Java 25. It exposes a REST API under `/api/v1` that handles the full user identity lifecycle — registration, email verification, login with local credentials or Google OAuth2, two-factor authentication, session management across devices, and role-based access control for admin operations.

## What's included

Auth Backend covers everything needed to secure a web application backend:

<CardGroup cols={2}>
  <Card title="JWT Authentication" icon="shield-halved" href="/concepts/authentication">
    Access tokens delivered via HttpOnly cookies or Bearer headers. Short-lived tokens with rotating refresh token rotation.
  </Card>
  <Card title="Google OAuth2" icon="google" href="/concepts/authentication">
    Stateless cookie-based OAuth2 flow. Google accounts are auto-verified and link by email.
  </Card>
  <Card title="Two-Factor Auth" icon="mobile-screen" href="/concepts/two-factor-auth">
    TOTP setup with QR code, one-time backup codes, and replay attack prevention via Redis.
  </Card>
  <Card title="Session Management" icon="layer-group" href="/concepts/sessions">
    Up to 4 active sessions per user with per-device tracking. Revoke any session remotely.
  </Card>
  <Card title="Password Reset" icon="key" href="/api/auth/password-reset">
    OTP-based recovery via email. Successful reset revokes all active sessions.
  </Card>
  <Card title="Rate Limiting" icon="gauge-high" href="/concepts/rate-limiting">
    Bucket4j + Caffeine rate limiting per operation category, keyed on user ID or client IP.
  </Card>
  <Card title="Avatar Uploads" icon="image" href="/api/users/avatar">
    Image validation, dimension checks, re-encoding, and Cloudinary storage.
  </Card>
  <Card title="Role-Based Access" icon="user-shield" href="/api/users/admin">

## Getting started

<Steps>
  <Step title="Start infrastructure">
    Spin up PostgreSQL 17 and Redis 7 with Docker Compose:
    ```bash
    docker compose up -d
    ```
  </Step>
  <Step title="Configure environment">
    Create an `application-local.properties` file (or set environment variables) with your database credentials, JWT secret, Cloudinary keys, and Resend API key. See [Configuration](/configuration) for the full list.
  </Step>
  <Step title="Run the application">
    ```bash
    ./gradlew bootRun
    ```
    The API is available at `http://localhost:8080/api/v1`. Swagger UI is at `http://localhost:8080/swagger-ui.html`.
  </Step>
  <Step title="Register and authenticate">
    ```bash
    # Register a new account
    curl -X POST http://localhost:8080/api/v1/auth/register \
      -H "Content-Type: application/json" \
      -d '{"name":"Jane","email":"jane@example.com","password":"S3cure!Pass"}'

    # Verify your email, then log in
    curl -X POST http://localhost:8080/api/v1/auth/login \
      -H "Content-Type: application/json" \
      -c cookies.txt \
      -d '{"email":"jane@example.com","password":"S3cure!Pass"}'
    ```
    Session cookies (`access_token`, `refresh_token`) are written automatically. See the [Quickstart](/quickstart) for a full walkthrough.
  </Step>
</Steps>

## API base URL

All endpoints share the prefix `/api/v1`. Responses use standard HTTP status codes. Errors follow the [RFC 9457 `ProblemDetail`](/api/errors) format.

```
Base URL: http://localhost:8080/api/v1
```

<Note>
  Interactive API documentation is available at `http://localhost:8080/swagger-ui.html` when the application is running. The OpenAPI spec is available at `/v3/api-docs`.
</Note>
